# Health strip table (fit-parser `--strip-health` and `--strip-hr`)

GENERATED by `tools/gen_health_table.py` from `docs/health-strip-table.tsv`. Edit the TSV, not this file.

Source: Garmin FIT SDK profile 21.158 (`third_party/fit-sdk/cpp/fit_profile.hpp`), every message and every field of it.

Two modes use this one table:

- `--strip-health`: removes every physiological and biomechanical value (heart rate, power, cadence, ...). Column "health".
- `--strip-hr` (v2.5.0): removes heart rate and other body data, but keeps power, cadence, pedalling dynamics, work,
  e-bike motor power, standing time and trainer resistance (for bike part wear). Column "hr".
  It removes a subset of what `--strip-health` removes; whole messages, developer data and the rules below are the same in both modes.

## Rules

1. **Allow-list.** Only the messages in the first table survive, and in them only the fields marked KEEP.
   Everything else is removed: all other global messages, fields the profile does not know, and messages the profile does not know.
   A field added to the profile in a later SDK is therefore removed until someone decides to keep it.
2. **All developer data goes**: `developer_data_id`, `field_description` and the developer fields on every message
   (CORE body temperature, Stryd power, Moxy and friends carry their values there; their meaning cannot be trusted).
3. **Event messages** pass only for the event types marked KEEP in the event table. Their `data` field means a
   heart rate / power / cadence threshold for the alert events, so those events are dropped whole, and an event
   without an `event` value or with a value the profile does not know is dropped too.
4. Kept: time, position, altitude, distance, speed, ambient temperature, grade, GPS accuracy, events, laps and sessions
   (times, distances, ascent, speed, sport), device and file info (including sensor battery).
5. Components: the output is re-encoded from the original fields only (expanded component fields are discarded first).
   Kept fields whose components feed another field only feed kept fields (checked: `record.altitude` -> `enhanced_altitude`,
   `record.speed` -> `enhanced_speed`, `record.compressed_speed_distance` -> `speed`, `distance`; lap and session speed / altitude likewise).
   The one exception is `event.data` -> `score` / `opponent_score` (sport_point subfield); those fields are removed and the event is dropped.
